# Kubernetes Mission Lab manifests

These manifests create an isolated `mission-control-lab` namespace with a five-replica `satellite-control-fleet` Deployment and a ClusterIP Service. The Pods use the `satellite-agent` container name and Kubernetes-generated Pod names beginning with `satellite-control-fleet-`. They do not modify existing Docker Compose containers.

From the repository root, apply with:

```bash
kubectl apply -f k8s/mission-control-lab/
kubectl -n mission-control-lab rollout status deployment/satellite-control-fleet
kubectl -n mission-control-lab get deploy,pods,svc -o wide
```

The Deployment targets five replicas. Deleting one lab-managed Pod should cause Kubernetes to create a replacement and reconcile the fleet back to five Pods, provided cluster capacity and image availability allow it. Pod names are generated by Kubernetes and can change after replacement.

Each demo Pod carries `app.kubernetes.io/managed-by=mission-control-kubernetes-lab`. The API checks that label and ReplicaSet ownership before permitting deletion. Remove the lab using `kubectl delete namespace mission-control-lab`.
